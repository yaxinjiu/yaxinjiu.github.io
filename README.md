# 高并发下的防线：限流（Rate Limiting）四大经典算法

**核心痛点**：突发流量容易打垮后端服务，必须通过限流保护系统稳定性。

**四大算法对比**：

* **固定窗口算法**：设定时间段（如 1 秒）和最大请求数。*缺点*：临界点可能出现双倍流量（如第 0.9 秒与第 1.1 秒各来上限流量）。
* **滑动窗口算法**：把时间切分为更细粒度的格，平滑解决固定窗口的临界突发问题。
* **漏桶算法（Leaky Bucket）**：请求先入桶，以固定速率“漏出”处理。*特点*：强制平滑出水，无法应对合法的突发流量。
* **令牌桶算法（Token Bucket）**：以固定速率向桶中放 Token，请求消耗 Token。*特点*：既限制了平均速率，又**允许一定程度的突发流量**（只要桶里有现成 Token）。
